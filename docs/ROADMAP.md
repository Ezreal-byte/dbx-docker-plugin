# Docker 插件后续路线

## 首期：0.2.0 Windows 验证候选

本期包含共享 Go 业务层、36 个 DBX AI/MCP 工具、默认关闭的连接级权限、删除/清理/部署预览、持久任务与取消、调用记录、有限事件查询、资源推荐问题、Windows Named Pipe、镜像/网络/卷详情和引用关系、网络连接与断开、卷和网络单项删除。

Compose 保留现有受控子集，并明确拒绝未支持的字段、变量插值、外部资源配置、多网络配置等；暂不等同于完整 Compose。容量优先使用 Engine 的卷磁盘用量，无法取得时显示未知。

仅交付 Windows 验证包。用户验证通过后再发布多平台产物、更新 DBX Store 上架 PR。

## 二期：日常管理闭环

按以下顺序拆分增量，每一步继续使用共享业务方法与权限目录：

1. 容器进程、文件系统变更查询；CPU/内存限制和重启策略更新。
2. 容器复制、重建，以及逐项结果明确的批量操作；复用预览令牌与任务中心。
3. 镜像流式导入/导出、仓库凭据引用。凭据由连接或凭据存储注入，不进入工具参数。
4. 网络 IPv6、完整 IPAM、别名和静态 IP；增加冲突检查和创建预览。
5. 事件时间线、资源变化刷新、任务进度、失败重试；重试写操作必须重新授权和预览。
6. 文件操作迁移到 Docker Archive API，减少容器内 `/bin/sh`、`stat`、`head` 依赖。

验收重点：资源更新与重建失败恢复、批量部分失败、流式大文件内存上限、凭据不进入日志、跨平台连接一致。

## 三期：部署与数据管理

1. 引入 Compose 标准解析库，处理变量、profiles、依赖和外部网络/卷。
2. 项目启停/删除、部署差异、健康等待和失败恢复；删除项目默认保留卷。
3. 通过受控辅助容器做卷备份、恢复和克隆；标注是否停写，恢复默认创建新卷。

验收重点：完整部署差异可审核，取消后的残留可追踪，备份恢复可校验，原数据卷在失败或删除项目时得到保护。

镜像构建、BuildKit、多平台构建、漏洞扫描独立排期。Swarm、Kubernetes、多主机编排不属于前三期范围。
